# Product Backlog

## Purpose

The Product Backlog is the single prioritized list of work for SHIAS.

It contains the major product capabilities required to achieve the Product Vision.

The backlog is continuously refined throughout the project and serves as the primary input to Sprint Planning.

Detailed User Stories, Tasks, and Bugs are managed in the team's project management tool (e.g., Jira, GitHub Projects, Azure DevOps).

---

# Backlog Principles

The Product Backlog is:

- Ordered by business value
- Continuously refined
- Estimated collaboratively
- Owned by the Product Owner
- Visible to the entire Scrum Team

Items at the top of the backlog should be more detailed than lower-priority items.

---

# Prioritization Criteria

Backlog items are prioritized using the following criteria:

1. Patient safety
2. Security
3. Regulatory compliance
4. Business value
5. User value
6. Technical dependencies
7. Development effort

# Backlog Refinement

Backlog refinement is performed continuously throughout development.

Activities include:

- Clarifying requirements
- Splitting large backlog items
- Re-estimating effort
- Reordering priorities
- Removing obsolete work

Refinement should ensure that upcoming backlog items are ready for Sprint Planning.

---

# Definition of Ready

A backlog item is considered ready for Sprint Planning when it:

- Has a clear objective
- Has defined acceptance criteria
- Has no unresolved dependencies
- Is estimated by the Development Team
- Can be completed within a single sprint

---

# Product Owner Responsibilities

The Product Owner is responsible for:

- Prioritizing backlog items
- Clarifying requirements
- Accepting completed work
- Balancing stakeholder needs
- Maintaining backlog quality

The Development Team contributes technical input but does not own backlog prioritization.

---

# Backlog Review

The Product Backlog is reviewed:

- During Backlog Refinement sessions
- Before Sprint Planning
- After Sprint Reviews
- When business priorities change

The backlog is a living artifact and evolves throughout the project.
